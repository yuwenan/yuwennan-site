## 01 / 农产品交易，要把双方的下一步接起来

采购方发布需求，供应方查看并报价，采购方确认合作对象后进入合同签署。每一步都有不同的操作人、信息和完成条件；页面能打开，还不够让交易顺利推进。

这个项目围绕采购大厅、供应大厅和企业后台，连接从供需信息到交易确认的关键环节。

## 02 / 我独立负责的范围

独立负责所承担交易模块的流程、状态和权限梳理，覆盖采购需求、供应商报价、购买与订单展示、法大大电子合同、发票上传及后续步骤衔接；参与前端调整、后端联调、问题跟进与交付。

工作重点是把“谁能操作、什么时候能操作、操作之后发生什么”落到页面和规则里，并推动前后台一致。项目已交付企业。

## 04 / 一个具体问题：双方签的，必须是同一份合同

联调时发现，双方分别进入签约操作可能各自创建合同，导致同一交易的合同关联不一致。问题需要从合同的创建和关联规则处理。

我的调整是与后端统一交易与合同的关联：同一笔交易对应同一份合同，双方进入各自签署环节时沿用这一关联；在关键操作时查询签署状态，决定提示等待还是继续推进。

| 当前情况           | 页面反馈与推进规则                 |
| ------------------ | ---------------------------------- |
| 本方尚未签署       | 进入该交易关联合同的签署环节       |
| 本方已签，对方未签 | 提示等待对方签署，保留当前交易状态 |
| 双方已完成签署     | 根据返回状态，继续后续业务步骤     |

这次问题让我把关注点从“签约按钮跳到哪里”，推进到“双方操作是否指向同一业务对象、状态能否正确回传”。
